# Week 2 Reflection

# Task 1
Brief A: This project should use the waterfall model. It should use this as there is a clear and concise brief, the requirements will not change, better model for safety concerns as all safety measures can be easily accounted for in the waterfall model, there is no pressure to release project but certificate schedule is 12-18 months which is better for waterfall. The only issue is customer involvement as they shouldn't be too involved since requirements do not need to change but if they want to change anything it will cause problems with the model.

Brief B: For this project Incremental Development should be used. It should be used as requirements are constantly changing from the customer. The customer has near daily interaction and will often change their mind when a version is done, there is no need for safety requirements to worry about which is good for this model. The only potential issue with this model is it may take longer than expected due to requirements constantly changing due to customer involment.

Brief C: For this project Iterative Development should be used. It should be used as all core functionality are needed but when customers use it requirements are expected to change. Iterative is good as they want to release a working product in a month that can be developed and refined. They have no safety issues to worry about. The only issue is that if requirements continue to change they may not meet thir deadline by the start of the academic year.
